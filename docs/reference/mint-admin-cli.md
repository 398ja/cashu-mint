# Mint admin CLI reference

The mint admin CLI is a Picocli application that orchestrates lifecycle, configuration, user, and alert workflows through a single `mint` command tree. The default launcher wires stub implementations of each port so operators can explore the interface without external dependencies before swapping in real adapters (see [`MintAdminCliApplication.java`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/MintAdminCliApplication.java) for the wiring).

## Command overview

| Command | Purpose | Key options | Output |
| --- | --- | --- | --- |
| `mint` | Display the current lifecycle state and high-level health of a mint instance (implemented by [`MintCommand.java`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/command/MintCommand.java)). | `--payload` / `--payload-file` to override the default `mintId` (`default-mint`) defined in [`MintStatusRequest.java`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/model/MintStatusRequest.java). | Single `MintStatusResponse` rendered as a table or JSON, using the model in [`MintStatusResponse.java`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/model/MintStatusResponse.java). |
| `mint config` | Manage configuration workflows for a mint via subcommands that adapt Picocli options onto the [`ManageConfigurationUseCase`](../../cashu-mint-admin/src/main/java/xyz/tcheeric/cashu/mint/admin/application/port/in/ManageConfigurationUseCase.java) contract (see [`MintConfigCommand.java`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/command/MintConfigCommand.java) and the `MintConfig*Command` implementations). | Common flags such as `--mint-id`, `--operator-id`, and `--version-tag` complement payloads supplied with `--payload`/`--payload-file`, while targeted commands add domain-specific options like `--target-revision` or `--deployment-ticket`. | Each subcommand renders the resulting `ConfigurationWorkflowResponse` from the use case, making full workflow state visible in table or JSON format. |
| `mint users` | Inspect operator accounts, including inactive members when needed (implemented by [`MintUsersCommand.java`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/command/MintUsersCommand.java)). | `--mint-id` defines the scope and `--include-inactive` broadens the result set, mirroring the flags in [`MintUsersCommand.java`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/command/MintUsersCommand.java). | Produces a list of `MintUserRecord` entries rendered in the chosen format (see [`MintUserRecord.java`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/model/MintUserRecord.java)). |
| `mint alerts` | Review or filter operational alerts by severity (implemented by [`MintAlertsCommand.java`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/command/MintAlertsCommand.java)). | `--mint-id` and `--severity` determine the alert scope when no payload is supplied, following [`MintAlertsRequest.java`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/model/MintAlertsRequest.java). | Returns a list of `MintAlertRecord` objects for the requested severity threshold (see [`MintAlertRecord.java`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/model/MintAlertRecord.java)). |

## Shared I/O options

Every command mixes in [`CommandIOOptions`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/command/CommandIOOptions.java), which adds consistent flags for payload and rendering control. Inline payloads and file-based payloads are mutually exclusive, and the CLI accepts JSON or YAML via `--input-format`. The `--output-format` flag switches between table and JSON renderers, using the enum values defined in [`InputFormat`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/io/InputFormat.java) and [`OutputFormat`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/io/OutputFormat.java).

Payloads are decoded with the shared [`CommandPayloadMapper`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/io/CommandPayloadMapper.java), which already registers Jackson modules for JSON and YAML parsing. Responses flow through the [`ResponseRenderingService`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/io/ResponseRenderingService.java), which ships with both [`JsonResponseRenderer`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/io/JsonResponseRenderer.java) and [`TableResponseRenderer`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/io/TableResponseRenderer.java) implementations out of the box.

## Default stub data

Out of the box the CLI uses deterministic stub adapters so you can try every command offline. These stubs return hard-coded status snapshots, configuration workflow artefacts, operator rosters, and alert lists until you replace them with real adapters. Review [`MintAdminCliApplication`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/MintAdminCliApplication.java) for the default wiring and the stub implementations under [`StubMintStatusPort`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/port/stub/StubMintStatusPort.java), [`StubManageConfigurationUseCase`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/port/stub/StubManageConfigurationUseCase.java), [`StubMintUsersPort`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/port/stub/StubMintUsersPort.java), and [`StubMintAlertsPort`](../../cashu-mint-admin-cli/src/main/java/xyz/tcheeric/cashu/mint/admin/cli/port/stub/StubMintAlertsPort.java).

When you are ready to connect to the REST API, follow the dedicated how-to in the How-to guides section.
