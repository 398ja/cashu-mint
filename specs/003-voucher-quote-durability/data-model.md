# Phase 1 Data Model: Voucher Quote Durability and Funding-Source Binding

**Feature**: 003-voucher-quote-durability
**Date**: 2026-05-22
**Source**: Phase 0 research (`research.md`)

Five new tables (one parent + three children via JOINED
inheritance for funding, plus quote and issuance) + four Flyway
migrations. All amount fields are `long`. All timestamps from
PostgreSQL `now()`. Hibernate Envers audit-tracks the parent
entities (`voucher_quote`, `voucher_funding`, `voucher_issuance`)
plus per-variant subclass tables for funding.

---

## Entity: VoucherQuote (sibling to MintQuote)

Durable record of a voucher mint quote. Sibling to spec-001's
`MintQuote` (research R1) — no inheritance.

| Field | Type | Constraints | Notes |
|---|---|---|---|
| `quote_id` | `VARCHAR(64)` | PK, NOT NULL | Distinct namespace from `mint_quote.quote_id`; cross-table uniqueness enforced at application layer |
| `voucher_type` | `VARCHAR(32)` | NOT NULL | e.g. `customer_paid`, `merchant_funded`, `iou` — informational; the funding row is authoritative |
| `face_value` | `BIGINT` | NOT NULL, > 0 | Spendable face value the voucher represents |
| `charged_amount` | `BIGINT` | NOT NULL, > 0 | Amount the customer / merchant was charged (may differ from face_value when fees apply) |
| `fee` | `BIGINT` | NOT NULL, >= 0 | `charged_amount - face_value` (or 0); persisted for audit |
| `unit` | `VARCHAR(16)` | NOT NULL | e.g. `sat`, `eur` |
| `merchant_id` | `VARCHAR(255)` | NULLABLE | npub or principal id of the merchant (when merchant-funded or IOU) |
| `customer_id` | `VARCHAR(255)` | NULLABLE | npub or principal id of the customer (when customer-paid) |
| `funding_id` | `VARCHAR(64)` | NULLABLE | FK → `voucher_funding.funding_id`. Set when funding is established; NULL while quote is awaiting funding |
| `lifecycle_state` | `VARCHAR(16)` | NOT NULL, default `UNFUNDED` | See state machine below |
| `idempotency_key` | `VARCHAR(255)` | NULLABLE, UNIQUE when not NULL | Client-supplied; used by the idempotency layer (FR-009) |
| `request_hash` | `CHAR(64)` | NOT NULL | SHA-256 of canonical request (tamper detection) |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, default `now()` | DB clock |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL, default `now()` | |
| `version` | `BIGINT` | NOT NULL, default 0 | JPA `@Version` |

**Indexes**:
- PRIMARY KEY (`quote_id`)
- UNIQUE on `idempotency_key` (partial index where IS NOT NULL)
- INDEX on `lifecycle_state`
- INDEX on `merchant_id`
- INDEX on `funding_id`

**Lifecycle State Machine**:

```text
              (create quote — idempotency_key checked)
                       │
                       ▼
                 ┌──────────┐
                 │ UNFUNDED │
                 └─────┬────┘
                       │ funding resolved
                       │ (CAS: UNFUNDED -> FUNDED;
                       │  voucher_quote.funding_id set)
                       ▼
                  ┌────────┐
                  │ FUNDED │
                  └────┬───┘
                       │ client mints with matching blinded outputs
                       │ (CAS: FUNDED -> ISSUING)
                       ▼
                 ┌─────────┐
                 │ ISSUING │
                 └────┬────┘
                      │ signatures + IssuanceRecord (spec 001) + VoucherIssuance committed
                      │ (CAS: ISSUING -> ISSUED)
                      ▼
                 ┌────────┐
                 │ ISSUED │ (terminal, NUT-19 idempotent replay)
                 └────────┘

   Side branches:
     UNFUNDED -> EXPIRED  (TTL elapsed without funding)
     FUNDED   -> EXPIRED  (paid but never minted within TTL)
     any      -> FAILED   (operator triage)
```

Transitions are compare-and-set conditional UPDATEs, mirroring
spec 001.

## Entity: VoucherIssuance

Append-only join row linking voucher quote → funding →
spec-001 `IssuanceRecord`. Answers the FR-005 audit query in one
indexed hop.

| Field | Type | Constraints | Notes |
|---|---|---|---|
| `voucher_quote_id` | `VARCHAR(64)` | PK, NOT NULL, FK → `voucher_quote.quote_id` | One issuance per voucher quote |
| `funding_id` | `VARCHAR(64)` | NOT NULL, FK → `voucher_funding.funding_id` | |
| `issuance_id` | `VARCHAR(64)` | NOT NULL | **DENORMALISED MIRROR** of `voucher_quote_id`. Retained for forward compatibility (e.g. a future shared issuance ledger). **Implementation reality (PR #321 review fix)**: voucher issuance does NOT write to spec-001's `issuance_record`. That table FKs its `quote_id` to `mint_quote(quote_id)` and voucher quoteIds live in `voucher_quote`, so any attempt to write there throws `DataIntegrityViolationException`. `voucher_issuance` IS the voucher ledger; no second-table write. No FK declared on this column because it intentionally references a column that doesn't enforce voucher namespace overlap with `mint_quote`. |
| `outputs_hash` | `CHAR(64)` | NOT NULL | Mirror of `IssuanceRecord.outputs_hash` for fast voucher audits without joining |
| `issued_at` | `TIMESTAMPTZ` | NOT NULL, default `now()` | |

**Indexes**:
- PRIMARY KEY (`voucher_quote_id`)
- INDEX on `funding_id` ("which vouchers did funding X back?")
- INDEX on `issuance_id`

**Append-only contract**: same as `IssuanceRecord` / `WebhookEvent`.
No UPDATEs/DELETEs from application code.

## Idempotency Cache

Spec 003 introduces an `idempotency_key` durable cache (research
R5), separate from the spec-001 quote tables.

### Entity: VoucherIdempotencyKey

| Field | Type | Constraints | Notes |
|---|---|---|---|
| `idempotency_key` | `VARCHAR(255)` | PK, NOT NULL | Client-supplied |
| `principal_id` | `VARCHAR(255)` | NOT NULL | Authenticated principal — keys are scoped per-principal so two principals can use the same key without colliding |
| `request_hash` | `CHAR(64)` | NOT NULL | SHA-256 of canonical request |
| `response_status` | `INTEGER` | NOT NULL | HTTP status code returned |
| `response_body_json` | `JSONB` | NOT NULL | Serialised response |
| `expires_at` | `TIMESTAMPTZ` | NOT NULL | TTL (e.g. 24 hours) |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, default `now()` | |

**Indexes**:
- PRIMARY KEY (`idempotency_key`, `principal_id`)
- INDEX on `expires_at` (TTL sweep)

**Semantics**: A retry with the same `(idempotency_key, principal_id)`
AND `request_hash` returns the cached response; a retry with the
same key but a different request_hash is rejected with a typed
tamper error.

## Flyway Migrations

Four SQL files in
`cashu-mint-jpa/src/main/resources/db/migration/`:

1. `V20260524_001__create_voucher_quote.sql`
2. `V20260524_002__create_voucher_funding.sql` (parent + 3 child
   tables in one migration for atomic visibility)
3. `V20260524_003__create_voucher_issuance.sql`
4. `V20260524_004__create_voucher_idempotency_key.sql`

(Optional `V20260524_005__migrate_in_memory_vouchers.sql` was
considered but rejected per research R8 — operators drain the
in-memory registry instead.)

Ordering: `voucher_funding` first (target of FK from
`voucher_quote.funding_id` and `voucher_issuance.funding_id`),
then `voucher_quote`, then `voucher_issuance`. The migration list
above re-orders for that constraint.

Online-safe: pure DDL on new tables; no existing-table column
additions. Brief table-creation locks only.

## State Transition Invariants (summary)

For every `VoucherQuote` row across its lifetime:

- At most one row in `VoucherIssuance` (PK on `voucher_quote_id`).
- For every `lifecycle_state = ISSUED` voucher quote:
  - `funding_id IS NOT NULL`.
  - The referenced `VoucherFunding` row's `amount` and `unit`
    equal `voucher_quote.charged_amount` and `voucher_quote.unit`.
  - There is exactly one `VoucherIssuance` row with the matching
    funding link, and a spec-001 `IssuanceRecord` keyed by the
    voucher's `quote_id`.
- For every `IssuedVoucher.face_value` summed across the mint, the
  cumulative voucher liability equals the cumulative funding sum
  across the three `VoucherFunding` subclasses (FR-005 daily
  reconciliation query, broken down by `funding_source` so the
  operator can see the IOU liability class separately).
- For every `MerchantIouFunding` row, the `policy_profile`
  matches the profile in which it was issued; rows where
  `policy_profile = 'prod'` AND the current profile policy is
  `DENY` are flagged for operator review.

## Out of Scope

- Retention / archival policy for `voucher_issuance` (append-only
  growth).
- Per-merchant policy on IOU acceptance (R6 long-term).
- Cross-mint voucher portability (today: one mint per instance).
- Voucher revocation / refund flow (entire separate feature).
