# M2 Settings and Configuration (CLI Phase)

## Overview
Deliver configuration governance entirely through the CLI so administrators can adjust parameters, rotate keys, and audit change
s without relying on any web components. UI work will wait until the CLI experience is proven in production.

## Technical analysis alignment
- Mirror the property-driven gateway resolution described under
  [gateway integration and configuration](../../docs/explanations/technical-analysis.md#gateway-integration-and-configuration)
  so CLI commands manipulate the same settings surfaces.
- Surface the metadata sources cataloged in [scope and context](../../docs/explanations/technical-analysis.md#scope-and-context)
  when building validation, previews, and drift detection.

## Deliverables
- Configuration domain model covering rate limits, fee schedules, key rotation policies, payout settings, and environment variab
les.
- Versioned configuration service exposing preview, diff, apply, and rollback capabilities consumable via CLI.
- CLI commands (`mint config set`, `mint config diff`, `mint config rollback`) with inline validation and change impact summarie
s in terminal output.
- Secure key management workflows supporting HSM integrations, offline signing, and approval gating for sensitive operations tri
ggered from the CLI.
- Audit artifacts detailing who changed which setting, when, and through which interface, prioritizing CLI provenance fields.
- Operator documentation covering scripting examples, access controls, and rollback procedures for terminal use.

## Tasks
1. Implement configuration storage with immutable history (e.g., append-only table) and tagging of active revisions.
2. Build validation library covering business rules (fee bounds, rotation intervals, rate limit ceilings) and reuse it across API
and CLI layers.
3. Expose configuration endpoints with fine-grained RBAC and multi-factor prompts for high-risk updates invoked from the CLI.
4. Integrate key rotation tooling with secrets storage (vault/HSM) and schedule automation accessible from scripts.
5. Provide machine-readable outputs (JSON, YAML) and human-friendly terminal diffs for CLI commands.
6. Write unit tests for validation logic and integration tests simulating configuration lifecycle including rollback scenarios in
voked through CLI.
7. Produce CLI-centric runbooks and tutorials describing safe configuration change procedures.

## Exit Criteria
- Administrators can manage all configuration lifecycle operations exclusively from the CLI with full audit trails.
- Sensitive operations enforce validation, RBAC, and approval flows suitable for terminal execution.
- Documentation and automated tests cover expected CLI scripting and recovery workflows.

## Deferred Web Scope (Post-CLI)
- Web forms with inline validation, diff visualization, and change impact summaries that reuse the CLI validation layer.
- UI affordances for reviewing configuration history once CLI usage patterns inform the optimal UX.
