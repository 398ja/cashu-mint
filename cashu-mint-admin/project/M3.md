# M3 Mint Status and Health (CLI Phase)

## Overview
Deliver observability and health reporting entirely through terminal tooling. Dashboards and other browser artifacts will be lai
d on later, once the telemetry and CLI reporting have proven reliable.

## Deliverables
- Metrics ingestion pipeline capturing issued tokens, redemptions, reserve levels, liquidity inflows/outflows, latency, error ra
tes, and infrastructure health signals.
- Time-series storage and aggregation layer supporting per-mint and fleet-wide analytics.
- CLI commands (`mint stats`, `mint stats --historical`, `mint uptime`) outputting tables or JSON suitable for automation.
- Status and health-check endpoints (REST/gRPC) providing machine-readable summaries for monitoring systems and CLI rendering.
- Alert hooks and export options that allow integration with external observability platforms from the CLI.
- Documentation describing telemetry schema, CLI usage examples, and integration tips for terminal-driven monitoring.

## Tasks
1. Define telemetry schema, retention policies, and data sampling strategies balancing accuracy and cost.
2. Implement collectors/agents that stream metrics from mint instances into the admin telemetry service.
3. Add CLI rendering utilities for tabular, JSON, and CSV outputs with pagination support.
4. Integrate with external observability tools (Prometheus, OpenTelemetry, Grafana) via adapters to feed CLI users and automation.
5. Create alerting hooks that consume metrics service events and expose them through CLI integrations (handoff to M6).
6. Test metric accuracy and endpoint reliability with automated and manual scenarios focused on CLI consumption.
7. Publish runbooks for common monitoring tasks, troubleshooting patterns, and automation scripts using the CLI outputs.

## Exit Criteria
- Operators can query real-time and historical mint health exclusively via CLI commands and exports.
- Telemetry feeds support automation, alerting, and external integrations validated through CLI scenarios.
- Documentation and tests verify schema stability and reporting accuracy for terminal workflows.

## Deferred Web Scope (Post-CLI)
- Dashboard layouts and visualization presets that consume the established telemetry APIs.
- Browser-based export and sharing experiences tailored for UI users once CLI feedback clarifies data priorities.
