# M3 Configuration Governance Use Case

## Objective
Deliver the `ManageConfiguration` use case so administrators can version, validate, diff, approve, and rollback configuration
sets while maintaining CLI-first ergonomics and audit traceability.

## Scope
- Extend configuration entities to model revision history, schema validation results, and approval checkpoints.
- Provide CLI and REST flows for authoring, previewing, applying, and rolling back configuration sets.
- Integrate with secrets management and notification policies to ensure sensitive updates honour security requirements.

## Workstreams
### Enterprise Rules
- Enhance `ConfigurationSet` with diff computation, compatibility checks against active mint state, and rollback safeguards.
- Link revisions to `MintAggregate` and `NotificationPolicy` so lifecycle workflows can reference configuration metadata.
- Store validation reports and approval artefacts within the domain model for audit replay.

### Application Business Rules
- Implement `ManageConfiguration` interactor handling submission, validation, staged approval, apply, and rollback operations.
- Orchestrate schema validators, policy engines, and approval workflows through injected ports.
- Trigger notification output ports when approvals are requested or applied, reusing domain events defined previously.

### Interface Adapters
- Build CLI commands (`mint config submit`, `mint config preview`, `mint config apply`, `mint config rollback`) with
  YAML/JSON input, diff rendering, and optional non-interactive modes.
- Add REST endpoints for automation and integration with infrastructure-as-code tools, mirroring CLI behaviours.
- Provide presenters that generate diff artefacts, validation summaries, and audit references consumable by scripts.

### Frameworks & Drivers
- Implement persistence adapters for configuration history tables with immutable revisions and active revision markers.
- Integrate with schema validation engines (JSON Schema, custom validators) and secure secret storage ports.
- Configure transactional outbox messages for configuration change events and update CLI/REST error mapping accordingly.

## Deliverables
- Fully functional `ManageConfiguration` interactor with unit tests covering validation failures, approvals, and rollbacks.
- Database migrations introducing append-only revision storage, approval state, and linkage to lifecycle history.
- CLI/REST implementations demonstrating preview, diff, apply, and rollback flows with machine-readable outputs.
- Documentation and runbooks covering configuration governance, including examples for automation pipelines.

## Acceptance Criteria
- Administrators can manage configuration lifecycle entirely from CLI or API while satisfying validation and approval policies.
- Configuration changes emit audit events and optional notifications, and history is queryable for compliance reviews.
- Tests exercise positive, negative, and rollback flows; documentation references the same commands and endpoints.
- Secrets and sensitive fields are stored via vault adapters, never persisted in clear text within configuration revisions.
