# M2 Mint Lifecycle Control Use Case

## Objective
Deliver the full `ManageMintLifecycle` interactor with CLI-first workflows for creating, updating, pausing, resuming, and
retiring mints, while producing auditable events and asynchronous hooks for future adapters.

## Scope
- Implement lifecycle orchestration inside the use-case layer, coordinating with repositories, audit services, and event
  publishers via ports.
- Provide CLI commands and REST endpoints that exercise the use case with validation, idempotency, and progress reporting.
- Persist lifecycle history, correlating state transitions with configuration revisions and operator metadata.

## Workstreams
### Enterprise Rules
- Finalize state machine rules in `MintAggregate`, including guard clauses for invalid transitions and approval requirements.
- Extend `AuditTrail` to capture lifecycle-specific fields (reason codes, ticket references, automation context).
- Associate lifecycle events with configuration references and notification policies for downstream processing.

### Application Business Rules
- Implement the `ManageMintLifecycle` interactor with methods for create/update/pause/resume/retire.
- Introduce transactional boundaries and rollback semantics; ensure retries are handled by adapters rather than the interactor.
- Emit structured domain events to the output port for asynchronous notification and read-model updates.

### Interface Adapters
- Build CLI commands (`mint create`, `mint update`, `mint pause`, `mint resume`, `mint retire`) using JSON/YAML payload support
  and machine-readable responses.
- Add REST controllers that expose equivalent endpoints with authentication, RBAC filters, and consistent error mapping.
- Produce presenters that format lifecycle summaries for CLI tables, JSON exports, and API responses.

### Frameworks & Drivers
- Implement persistence adapters for mint aggregates, lifecycle history tables, and transactional outbox writers.
- Configure scheduling hooks or message queues (if available) to process lifecycle events after commits.
- Add logging correlation IDs that tie CLI invocations to audit records for observability.

## Deliverables
- Production-ready `ManageMintLifecycle` use case with comprehensive unit tests covering success and rejection paths.
- Database migrations for lifecycle history tables, approval states, and audit linkage.
- CLI command suite with confirmation prompts, dry-run mode, and progress tokens for long-running operations.
- REST endpoints with OpenAPI documentation and contract tests ensuring payload compatibility with the CLI.
- Scenario documentation and runbooks demonstrating lifecycle management via CLI and API scripts.

## Acceptance Criteria
- Operators can execute lifecycle workflows end-to-end from the CLI with verifiable audit entries and persisted state changes.
- REST/API consumers observe identical behaviour, response shapes, and error handling as the CLI.
- Domain events are published for downstream systems and can be inspected through the transactional outbox.
- Automated tests and documentation cover primary flows plus edge cases (invalid transitions, duplicate submissions, rollbacks).
