# M5 Operational Controls and Runbook Automation

## Objective
Ship the `ExecuteOperationalControls` use case so operators can trigger maintenance, recovery, and key rotation workflows from
the CLI with auditability, guardrails, and progress tracking.

## Scope
- Support scheduled and ad-hoc operational jobs (pause with drain, resync, backup restore, key rotation) with safe defaults.
- Provide orchestration for long-running tasks, including progress tokens, resumable states, and incident escalation.
- Embed audit context, approvals, and notification hooks for every operational command.

## Workstreams
### Enterprise Rules
- Enhance entities with operational guardrails (required quorum, maintenance windows, rollback targets).
- Model runbook definitions and execution history as domain concepts linked to `MintAggregate` and `OperatorAccount`.
- Capture incident references and remediation metadata inside `AuditTrail` entries.

### Application Business Rules
- Implement `ExecuteOperationalControls` interactor coordinating job planning, execution, and completion callbacks.
- Integrate approval flows, safety checks, and dependency ordering before operations begin.
- Produce progress events and completion artefacts for CLI polling and documentation storage.

### Interface Adapters
- Build CLI commands (`mint ops plan`, `mint ops execute`, `mint ops status`, `mint ops cancel`) with confirmation prompts,
  schedule options, and human-readable progress displays.
- Add REST endpoints enabling automation platforms to trigger the same operations with JWT-authenticated requests.
- Provide presenters that stream progress to CLI users and serialize execution artefacts for integration with ticketing systems.

### Frameworks & Drivers
- Implement orchestration drivers (Spring Batch, custom scheduler, or message queues) managing long-running tasks.
- Configure persistence for job definitions, execution states, and compensation actions.
- Integrate with notification adapters to broadcast start/completion/failure events and with monitoring to raise incidents.

## Deliverables
- `ExecuteOperationalControls` use case covering planning, execution, cancellation, and completion, with unit tests for guardrails
  and failure handling.
- Persistence schema for job definitions, execution timelines, and associated audit metadata.
- CLI/REST tooling enabling operators to run runbooks, inspect status, and cancel or retry tasks.
- Documentation for operational scenarios (emergency pause, key rotation, data repair) referencing CLI commands and APIs.

## Acceptance Criteria
- Operational workflows execute end-to-end via CLI or REST with approvals, guardrails, and audit records enforced.
- Progress tokens allow operators to monitor long-running jobs and retrieve final artefacts or error reports.
- Notifications fire on start/completion/failure and integrate with the health monitoring milestone outputs.
- Automated tests simulate failure cases, ensuring retries, compensations, and rollbacks behave as designed.
