# M4 Mint Lifecycle Workspace

## Objective
Implement the mint lifecycle workspace that enables operators with `MINT_ADMIN` role to create, update, pause, resume, and retire mints with preview and confirmation steps.

## Scope
- Build mint list and detail views with lifecycle history, configuration links, and contextual actions.
- Deliver multi-step dialogs for create/update/pause/resume/retire flows that invoke preview endpoints before confirmation.
- Persist in-progress lifecycle forms locally to guard against accidental navigation or session expiry.
- Expose audit annotations and success/error messaging consistent with the technical analysis guidance.

## Workstreams
### Mint Directory and Detail Views
- Render sortable/filterable mint tables showing state, version tag, owner team, and last change timestamp.
- Provide detail pages summarising metadata, lifecycle timeline, and associated configuration revisions.
- Integrate deep links from dashboard and other modules into mint-specific context.

### Lifecycle Actions
- Implement stepper dialogs: input metadata, preview backend response, final confirmation with audit summary.
- Handle optimistic updates and state reconciliation after API responses, including partial failure surfaces.
- Enforce role guards that disable or hide actions for operators lacking `MINT_ADMIN`.

### Draft Persistence and Validation
- Auto-save draft inputs per mint in localStorage/sessionStorage with explicit clear/reset controls.
- Validate required fields, justification text, and version constraints before calling preview endpoints.
- Surface backend validation errors inline with actionable guidance and retry controls.

## Deliverables
- Lifecycle workspace screens, dialogs, and supporting services integrated with admin REST lifecycle endpoints.
- Automated unit/integration tests covering lifecycle flows, validation errors, and optimistic updates.
- Documentation updates linking to lifecycle tutorials and highlighting UI vs CLI parity.

## Acceptance Criteria
- Operators can perform lifecycle actions end-to-end with previews, confirmation prompts, and audit annotations recorded.
- Draft persistence protects against accidental data loss and clears after successful submission.
- Tests verify successful flows, validation handling, and role enforcement as part of `mvn verify`.
