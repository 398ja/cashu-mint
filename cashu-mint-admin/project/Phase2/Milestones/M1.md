# M1 Frontend Foundations and Build Integration

## Objective
Lay down the single-page application scaffolding, build pipeline hooks, and shared tooling required to deliver the Phase 2 admin web experience described in the specification and technical analysis.

## Scope
- Generate the TypeScript/React project structure with feature-based directories (`dashboard`, `mints`, `configuration`, `operators`, `alerts`, `activity-log`, `settings`).
- Integrate the bundler (Vite or Webpack) into the Maven lifecycle so `mvn verify` compiles static assets alongside the admin REST module.
- Establish linting, formatting, unit test harness (Jest + Testing Library), and Storybook or equivalent component preview tooling.
- Provide a base routing table and layout shell that renders placeholder routes for each feature pillar.

## Workstreams
### Tooling and Build Pipeline
- Configure Node/Yarn tooling via Maven plugins, setting up reproducible installs and cacheable builds.
- Add CI scripts to run lint, unit tests, and bundle generation, ensuring outputs land under `/admin/ui` for Spring Boot to serve.
- Define environment configuration strategy for API base URLs, telemetry endpoints, and feature flags.

### Application Shell
- Implement root layout with header, sidebar navigation placeholders, and responsive grid breakpoints from the UX deliverables.
- Wire React Router with guarded routes that defer rendering until authentication context is available.
- Stub shared providers (theme, query client, telemetry) to support later milestones.

### Quality and Developer Experience
- Enforce TypeScript strict mode and path aliases aligned with the module structure.
- Introduce automated accessibility linting (axe-core or eslint-plugin-jsx-a11y) to run during development builds.
- Document local development workflow, including commands for hot reload and integration with the admin REST service.

## Deliverables
- SPA project checked into the repo with feature folders, shared component library scaffolding, and initial layout shell.
- Maven build updates invoking frontend install/build steps as part of `mvn verify`.
- Developer documentation covering project setup, scripts, and architectural conventions.

## Acceptance Criteria
- Running `mvn verify` compiles the frontend bundle without manual steps and fails on lint or unit test regressions.
- Navigating to the admin REST static assets serves the placeholder shell with routes for all feature modules.
- Repository contains coding standards and contribution guidelines for the new frontend module.
