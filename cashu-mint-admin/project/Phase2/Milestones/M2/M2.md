# M2 Authentication, Session Management, and Role Guards

## Objective
Deliver the secure authentication shell, token handling, and role-aware routing controls that gate access to Phase 2 features according to the admin REST contract.

## Scope
- Implement login/token entry experience with validation and integration to admin REST health endpoints.
- Persist session tokens, active role selections, and correlation identifiers following security guidance (sessionStorage by default).
- Enforce role-based access via guarded routes, navigation visibility rules, and disabled action states.
- Surface session expiry warnings, error banners, and retry affordances for authentication failures.

## Workstreams
### Authentication Context
- Build a dedicated auth provider responsible for storing tokens, refreshing role metadata, and broadcasting session state.
- Implement secure clipboard copy controls for tokens with automatic masking and optional "remember me" behaviour.
- Capture inactivity timers that trigger warning modals and logout actions after the configured idle threshold.

### Role Awareness and Routing
- Fetch available roles per operator and expose selector controls in the global header consistent with UX design.
- Guard React Router routes based on required roles, rendering informative empty states when permissions are insufficient.
- Ensure API client wrappers automatically include `X-Admin-Token` and `X-Admin-Roles` headers on every request.

### Error Handling and Observability
- Provide consistent notification components for auth failures, permission denials, and network outages.
- Emit telemetry events when sessions start, roles switch, or logouts occur, correlating IDs with backend traces.
- Add automated tests covering token storage fallbacks, role switching, and idle timeout handling.

## Deliverables
- Authentication UI flow aligned with specification copy and timeouts.
- Shared hooks/utilities for authenticated API calls and role checking.
- Test suites validating session persistence, guard rendering, and error messaging.

## Acceptance Criteria
- Operators can authenticate, select roles, and navigate to permitted areas while restricted routes display clear messaging.
- Tokens default to session-scoped storage with optional opt-in to longer persistence and are cleared on logout or expiry.
- Automated tests cover success, failure, and timeout scenarios, running during `mvn verify`.
